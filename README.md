# Private Calendar MCP

Deleting an entire calendar container is permanently disabled, with no configuration or approval override. `commit_delete` can delete only one identified event or occurrence from its signed preview. Individually authorized event deletions remain subject to the normal consent and quota checks.

A personal macOS Calendar integration with a Swift EventKit broker, a dependency-free Python MCP gateway and a stdio adapter for local clients or an official private Secure MCP Tunnel. It uses the calendars already configured in macOS, including iCloud; no iCloud password is collected.

Calendar changes use two steps: `preflight_change` returns the complete signed before/after preview, then `commit_create`, `commit_modify` or `commit_delete` receives that entire preview through the host's normal confirmation policy. The native broker checks identity and freshness and journals the exact payload before one mutation attempt. There is no Terminal approval prompt, approval endpoint or caller-controlled approval flag. Host policy is not proof of a fresh human click.

The deployed recurrence release adds daily, weekly, monthly and yearly series creation, plus editing/deleting one identified occurrence. Series creation uses `scope:"series"` with typed `fields.recurrence`; occurrence edits/deletes use `scope:"this"`. Future-occurrence and entire-series modification/deletion remain unsupported because the backend cannot prove complete series exception topology for safe execution and recovery. Version-3 signed previews disclose recovery: a deleted recurring occurrence can be recreated only as a standalone copy with new provider identity, leaving the series exclusion in place and without inheriting future series edits. Existing recurring deletes without that signed contract remain blocked. See [recurring events](docs/setup.md#individual-and-recurring-events). Multiple display alerts can be supplied at creation or replaced on an existing event through `fields.alerts`. Each of up to ten alerts uses `relative_minutes` (negative before start, positive after) or an absolute `at` timestamp with a UTC offset. Omission preserves existing alarms on modification; `[]` clears them. Adding, editing or removing an alert submits the complete desired list through the same signed preview and commit flow. See [event alerts](docs/setup.md#multiple-event-alerts) for examples and compatibility. This feature is deployed on the Studio with metadata-only verification; real Calendar alert delivery and refreshed ChatGPT presentation remain unverified.

Recovery retains detailed integration history for **five days by default**, configurable locally from 1 to 365 days. It adds MCP history browsing and signed rollback previews, plus a standalone native window for local review and recovery. Larger selections use a complete paginated inventory and explicit batches of up to 25 changes; each recovery write is independently checked and journalled. Expired details cannot be recovered, unknown outcomes remain protected, and recovery cannot reproduce provider identifiers or provenance. Requires macOS 14+, Swift 6 and Python 3.11+. Python runtime dependencies are standard library only. This is a private single-user integration, with no public ingress or public OAuth server. It covers all calendars exposed by macOS, including other configured accounts, subscribed calendars and read-only calendars.
