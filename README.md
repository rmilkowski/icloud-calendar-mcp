# Private Calendar MCP

A personal macOS Calendar integration with a Swift EventKit broker, a dependency-free Python MCP gateway and a stdio adapter for local clients or an official private Secure MCP Tunnel. It uses the calendars already configured in macOS, including iCloud; no iCloud password is collected.

Calendar changes use two steps: `preflight_change` returns the complete signed before/after preview, then `commit_create`, `commit_modify` or `commit_delete` receives that entire preview through the host's normal confirmation policy. The native broker checks identity and freshness and journals the exact payload before one mutation attempt. There is no Terminal approval prompt, approval endpoint or caller-controlled approval flag. Host policy is not proof of a fresh human click.

Native bulk-write protection allows dozens of ordinary changes while bounding cumulative destructive attempts: by default, 50 deletes per rolling hour and 200 per rolling 24 hours, plus 100 combined modifies/deletes per rolling hour and 500 per rolling 24 hours. Fresh durable intents count across calls, chats, calendars and restarts. Local operators can adjust the protected policy for larger jobs; ChatGPT confirmation still applies. See [write-safety configuration](docs/setup.md#bulk-modify-and-delete-protection). The upgraded Studio helper now includes this policy; live Calendar enforcement awaits the deferred macOS grant and has not been exercised by a real write. If preflight has no `safety` feedback, cumulative protection is not confirmed.

Recovery retains detailed integration history for **five days by default**, configurable locally from 1 to 365 days. It adds MCP history browsing and signed rollback previews, plus a standalone native window for local review and recovery. Larger selections use a complete paginated inventory and explicit batches of up to 25 changes; each recovery write is independently checked and journalled. Expired details cannot be recovered, unknown outcomes remain protected, and recovery cannot reproduce provider identifiers or provenance. See [retention and recovery](docs/setup.md#retained-history-and-recovery). The Studio now advertises all four recovery tools; production recovery mutations remain unverified.

Requires macOS 14+, Swift 6 and Python 3.11+. Python runtime dependencies are standard library only. This is a private single-user integration, with no public ingress or public OAuth server. It covers all calendars exposed by macOS, including other configured accounts, subscribed calendars and read-only calendars.
